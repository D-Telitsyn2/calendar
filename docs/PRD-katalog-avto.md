# PRD: каталог авто с пробегом из Telegram-канала

Документ для нового репозитория и нового чата. Читать сверху вниз и делать по этапам. Чужой код из репозитория, где лежит этот файл, к продукту не относится.

---

## 1. Зачем продукт

Готовый сайт-витрина для импортёра авто. Объявления живут в Telegram-канале клиента. Бот-админ канала забирает посты (и правки постов), вырезает телефоны и служебные блоки, кладёт машины на сайт.

Продаётся как внедрение под ключ + ежемесячное сопровождение. Не парсер чужих каналов «с улицы».

---

## 2. Что входит / что не входит

**Входит в первую версию**

- Публичный каталог: список, карточка, фильтры, SEO.
- Админка: правка карточки, скрыть/снять, очередь «на проверку».
- Бот: новые посты и отредактированные посты канала.
- Склейка альбома фото.
- Скачивание фото к себе (MinIO), не горячие ссылки Telegram.
- Разбор текста по шаблону + запасной разбор моделью, если не собрались обязательные поля.
- Вырезание контактов и «подвала» поста до публикации.
- Белая этикетка: название, логотип, телефон в шапке/подвале сайта (не в тексте объявления).
- Docker Compose на одном VPS.

**Не входит в первую версию**

- Скрытый сбор чужих каналов без бота-админа.
- Личный кабинет покупателя, оплата, бронь, 1С, WhatsApp-рассылки.
- Мультитенантность «много клиентов на одном инстансе» (каждый клиент = свой VPS или свой compose).
- Мобильное приложение.
- Автоудаление карточки при удалении поста в канале (у Bot API нет нормального события; снятие — руками или отдельным этапом позже).

## 3. Пользователи

| Кто | Что делает |
|---|---|
| Посетитель сайта | Смотрит машины, фильтрует, открывает карточку. Телефон импортёра — в шапке сайта, не в объявлении. |
| Менеджер клиента | Правит карточку, снимает с продажи, подтверждает кривой импорт. |
| Владелец канала | Добавляет бота админом, не пишет код. |
| Вы (внедрение) | Ставите Docker, прописываете токен, домен, шаблон разбора под формат их постов. |

## 4. Правило Telegram (обязательно)

Источник — **канал клиента**. Бот добавляется **администратором канала**.

События Bot API:

- `channel_post` — новый пост → создать/дополнить карточку.
- `edited_channel_post` — правка того же поста → переразобрать и обновить карточку, если менеджер не поставил «зафиксировать вручную».

Связка записи: `telegram_chat_id + telegram_message_id` (для альбома — ещё `media_group_id`).

Удаление поста боту обычно **не приходит**. Статус «снято с продажи» ставит менеджер.

## 6. Карта репозитория

```
/
  apps/web          # Next.js: публичный сайт + /admin
  apps/bot          # Grammy, webhook или long polling

  .env.example
  README.md
```

Публичные URL:

- `/` — каталог
- `/cars/[slug]` — карточка
- `/admin` — вход
- `/admin/cars` — список, фильтр «на проверке»
- `/admin/cars/[id]` — правка
- `/admin/settings` — бренд, курс, id канала, что вырезать

Бот и worker не торчат в интернет, кроме webhook бота (`/telegram/webhook`) если выбран webhook.

## 7. Модель данных

### 7.1. `Car`

| Поле | Смысл |
|---|---|
| id | uuid |
| slug | уникальный, для URL |
| status | `draft` / `review` / `published` / `hidden` / `sold` |
| source | `telegram` |
| telegramChatId | id канала |
| telegramMessageId | id сообщения (первое фото альбома или текстовый пост) |
| mediaGroupId | если альбом |
| rawText | полный текст поста как пришёл |
| parsedJson | JSON результата парсера |
| parseConfidence | 0–1 |
| parseErrors | список несобранных полей |
| manualLock | true = правки из Telegram не перезаписывают карточку |
| brand, model, generation | строки |
| year | int |
| engineVolumeLiters | decimal |
| horsePower | int |
| fuel | `petrol` / `diesel` / `hybrid` / `electric` / `unknown` |
| transmission | `at` / `mt` / `unknown` |
| drive | `fwd` / `rwd` / `awd` / `unknown` |
| mileageKm | пробег как в посте (км) |
| mileageNote | текст вроде «эквивалент российским 22 тыс.» |
| originCountry | DE / KR / CN / другое |
| equipment | text[] |
| priceEur | decimal, nullable |
| priceRub | int, nullable |
| priceNote | «под ключ до СПб», «курс может меняться» |
| title | человеческий заголовок карточки |
| descriptionPublic | текст без контактов и подвала |
| publishedAt, soldAt, createdAt, updatedAt | даты |

Индекс уникальный: `(telegramChatId, telegramMessageId)`.

### 7.2. `CarPhoto`

order, key в MinIO, width/height если есть, telegramFileId.

### 7.3. `Settings` (одна строка на инстанс)

siteName, logo, phoneHeader, workHours, city, eurRubRate, channelId, stripPatterns (список), reviewIfMissing (какие поля обязательны).

### 7.4. `AdminUser`

email + hash пароля. На старте один пользователь из `.env`.

## 8. Разбор поста

Пример входа (формат, под который заточить шаблон №1):

```
🚗 Доступен к заказу европейский Skoda Superb …
📅 Год выпуска 2023
⚙️ Двигатель: 1.5 л , 150 лс бензин
🔄 Пробег: 43 800 км (эквивалент российским 22 тысячам километров)
Комплектация: …
💰 Стоимость под ключ до Санкт Петербурга : 31 600 евро
(~ 3 220 000 руб) «Под ключ»
📞 Телефон …   ← вырезать
⏰ Время работы … ← вырезать
```

### 8.1. Вырезать до публикации на сайт

- телефоны (все форматы РФ, с пробелами и скобками);
- строки с 📞, «телефон для подбора»;
- время работы;
- username / t.me / vk / wa.me;
- email.

В `rawText` хранить оригинал. На сайте — только `descriptionPublic`.

### 8.2. Шаблон (первый проход, без модели)

1. Марка/модель из первой значимой строки (словарь марок: Skoda, BMW, Mercedes, Kia, Hyundai, Toyota, …).
2. Год: `Год выпуска\s+(\d{4})`.
3. Двигатель: литры, л.с., топливо.
4. Пробег: первое число + единица; скобку в `mileageNote`.
5. Блок «Комплектация» — до блока цены, резать по строкам в массив.
6. Цена: евро и опционально рубли; пометка «под ключ».
7. Страна по флагам/словам: Германия/🇩🇪 → DE, Корея, Китай.

Обязательные для автопубликации: brand, model, year, priceEur **или** priceRub.

Если чего-то нет → `status = review`, в админке бейдж.

### 8.3. Второй проход (модель)

Только если шаблон не собрал обязательные. Строгий JSON по zod-схеме. Не выдумывать цену. Нет в тексте — `null`.

### 8.4. Альбом фото

Сообщения с одним `media_group_id` копить 1.5–2 сек в Redis, потом одна задача «создать/обновить авто». Текст обычно в caption первого фото.

## 9. Поведение импорта

```
пост → bot → очередь ingest
  → склеить альбом
  → сохранить raw
  → скачать фото в MinIO
  → вырезать контакты
  → шаблон → (если дыры) модель
  → если карточки ещё нет:
        обязательные поля ок → published
        иначе → review
  → если карточка есть и manualLock=false:
        обновить поля из нового разбора, не затирать пустым null то, что уже было заполнено вручную (правило: пустой парсер не бьёт непустое поле)
  → если manualLock=true: только обновить rawText и фото, поля не трогать
```

Пост без машины (вакансия, отзыв, сторис): эвристика «нет цены и нет года и нет марки» → `review` или пропуск с записью в лог админки (`ImportLog`).

## 10. Публичный сайт

- Шапка: логотип, название, телефон из Settings, город.
- Список: фото, название, год, пробег, цена ₽ и/или €, бейдж «под ключ» если есть.
- Сортировка: новые, дешевле, дороже, год, пробег.
- Фильтры: марка, цена, год, пробег, топливо, страна.
- Карточка: галерея, характеристики, комплектация списком, примечание про курс, CTA «узнать» = `tel:` на телефон из Settings (не из поста).
- Нет индексирования `hidden` / `sold` / `review` / `draft`.
- `sitemap.xml`, нормальные title/description.
- Адаптив: мобильный первый (трафик с Telegram).

Пустые состояния: «сейчас нет авто» — спокойный текст, не ошибка.

---

## 11. Админка

Вход: email/пароль, сессия (лучше Auth.js / отдельная cookie).

Список авто: статус, дата поста, уверенность разбора, кнопка «открыть на сайте».

Карточка:

- все поля из §7.1;
- галерея: порядок, удалить фото;
- статус;
- `manualLock`;
- сырой текст поста (только чтение);
- список `parseErrors`.

Настройки: бренд сайта, телефон шапки, курс EUR/RUB (ручной), опция «пересчитывать ₽ от € по курсу при показе».

Первый вход: создать админа из `ADMIN_EMAIL` / `ADMIN_PASSWORD` при старте, если таблица пустая.

## 12. Этапы работ (делать строго по порядку)

Каждый этап заканчивается рабочим артефактом. Не начинать следующий, пока не выполнены критерии этапа.

### Этап 0. Каркас репозитория

1. `pnpm` workspaces: web, bot, worker, shared.
2. Docker Compose: `postgres`, `redis`, `minio`, `web`, `bot`, `worker`.
3. `.env.example`: `DATABASE_URL`, `REDIS_URL`, `S3_*`, `BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`, `ADMIN_*`, `OPENAI_API_KEY` (опционально), `OPENAI_BASE_URL`.
4. Prisma-схема по §7, миграция, seed настроек.
5. README: как поднять локально, как добавить бота админом канала.

**Готово когда:** `docker compose up` поднимает пустой сайт на localhost без падений.

### Этап 1. Публичный каталог на моках

1. Страницы `/` и `/cars/[slug]`.
2. Карточки из seed (2–3 авто, как в примере Skoda Superb).
3. Фильтры и сортировка на сервере (query в URL).
4. Вёрстка мобильная + десктоп.
5. SEO: title, og, sitemap.

**Готово когда:** по seed видно список и карточку, фильтр по марке работает, без бота.

### Этап 2. Админка

1. Логин.
2. CRUD статусов и полей авто.
3. `manualLock`.
4. Settings.
5. Очередь `review`.

**Готово когда:** можно спрятать машину и увидеть, что с публичного сайта она пропала.

### Этап 3. Загрузка фото в MinIO

1. Хелпер upload/get signed or public URL через прокси Next `/media/[...key]` (бакет не светить наружу без нужды).
2. Админка: загрузить фото вручную к карточке.

**Готово когда:** фото с MinIO открывается на карточке.

### Этап 4. Вырезание контактов и шаблонный парсер

1. Юнит-тесты на текст из §8 и ещё 3–5 вариаций (пробелы в телефоне, нет рублей, дизель, Корея).
2. Функции в `packages/shared`.
3. Не ходить в сеть.

**Готово когда:** тесты зелёные, телефоны не попадают в `descriptionPublic`.

### Этап 5. Бот + очередь

1. Grammy: `channel_post`, `edited_channel_post`.
2. Игнор постов не из `TELEGRAM_CHANNEL_ID`.
3. Буфер альбома в Redis.
4. Job `ingestTelegramPost`.
5. Скачать file_id через Bot API → MinIO.
6. Создать/обновить `Car`.

**Готово когда:** тестовый пост в канале (бот админ) появляется на сайте без телефона; правка цены в канале обновляет карточку; при `manualLock` цена с сайта не откатывается.

### Этап 6. Запасной разбор моделью

1. Если нет обязательных полей — job `llmParse`.
2. Zod-валидация ответа.
3. Нет ключа API → остаётся `review`, без падения воркера.

**Готово когда:** кривой пост без эмодзи-меток уходит в проверку или собирается моделью, ключ не обязателен для работы стенда.

### Этап 7. Полировка к продаже

1. Лог импорта в админке (успех / review / ошибка).
2. 404, пустой каталог.
3. `robots.txt`, favicon, мета.
4. Бэкап: инструкция pg_dump + mc mirror MinIO в README.
5. Скрипт `scripts/provision.sh` или глава README «выкат на VPS».
6. Лимит размера фото, watermark не нужен в v1.

**Готово когда:** по README человек без контекста поднимает прод на чистом VPS за один проход.

### Этап 8. Приёмка на реальном канале клиента

1. Подставить их `BOT_TOKEN` и канал.
2. Прогнать 20 последних постов (разовый backfill: `getUpdates` не даст историю; для истории — ручной экспорт или Bot API не тянет старое).
3. **История канала:** в v1 backfill не обещать через Bot API. Варианты: клиент репостит актуальные в канал; или отдельная задача на userbot/экспорт **только с согласия владельца канала**, не в v1.
4. Починить шаблон под их мелкие отличия формата.
5. Чеклист внизу этого файла — все пункты да.

## 13. Backfill (честно)

Bot API **не читает историю** канала. Живой поток — только новые и отредактированные после добавления бота.

Для витрины на старте: менеджер публикует актуальные авто заново **или** вручную заводит в админке. Не строить v1 на парсинге web.t.me и MTProto.

## 15. Критерии приёмки v1

- [ ] Каталог открывается с телефона.
- [ ] В карточке нет телефонов и «времени работы» из поста.
- [ ] Телефон импортёра есть в шапке/подвале из Settings.
- [ ] Новый пост с фото → карточка за 1–2 минуты.
- [ ] Альбом из нескольких фото → одна карточка, все фото.
- [ ] Правка цены в канале → цена на сайте, если нет manualLock.
- [ ] Нет цены/марки → статус «на проверке», на сайте нет.
- [ ] Скрыть в админке → с сайта пропала.
- [ ] Sold не в выдаче, в админке видна.
- [ ] `docker compose up` из README на чистой машине.
- [ ] Юнит-тесты парсера на эталонном посте Skoda и на посте с рваным телефоном.

## 18. Риски

| Риск | Что делать |
|---|---|
| Формат постов плывёт | Очередь review + правка шаблона на сопровождении |
| Альбом приходит пачкой | Буфер 2 с по media_group_id |
| Менеджер правил сайт, потом пост в канале | manualLock |
| Нет истории через бота | Честно сказать на пресейле |
| Фото Telegram протухают | Только свои копии в MinIO |
| Юр. риск чужого канала | Не делать; продаём только владельцу канала |
